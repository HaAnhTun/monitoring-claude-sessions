# 0002 Python-syntax regexes translated to JavaScript `v`-mode, accepted only when exact

Status: Amended by 0067 (proposed Phase 1, 2026-10-11). Owner: instances/config/ops design (`docs/design/01-instances-config-ops.md` section 2.8).

## Context
`config.json` stores Python-syntax regexes (`session_rules[].match`, `attempts.start/end`) shared with the legacy engine (D5). The live
V9 task uses `(?P<name>...)`, which JavaScript rejects. Many constructs differ silently: `$` before a final newline, `.` and line
terminators, `\A`/`\Z`, Unicode `\w`/`\d`/`\s`/`\b`, case folding, captures inside repetitions.

## Decision
- Keep the Python text as the stored form; translate at load with a parser for a documented subset of CPython `sre_parse` and an
  emitter producing JavaScript `v`-mode source. Flags: always `v`; `i` for global IGNORECASE; `y` for `attempts` (Python `re.match`).
  JS `m`/`s` are never used: `^`, `$`, `.` are emulated (`(?<![\s\S])`, `(?=\n?(?![\s\S]))`, `[^\n]`).
- Class mappings: `\w` -> `[\p{L}\p{N}_]`, `\d` -> `[\p{Nd}]`, `\s` -> an explicit 29-code-point class, `\b` via lookarounds on `\w`.
- Reject loudly (`UNSUPPORTED_*`, `SYNTAX`, `INEXACT_SEMANTICS`): verbose/locale flags, possessive/atomic/conditional, `\N{}`, `\z`,
  `(?<n>)`, ambiguous sets, repeated assertions, captures inside repetitions that an iteration can skip, IGNORECASE with non-ASCII
  literals. Under IGNORECASE, ASCII `i`/`I` also match U+0130/U+0131 (Python behaviour).
- Golden tests generated by Python (dev tool), committed; an opt-in differential run on a real config prints counts only.

## Consequences
- Existing configs (V9, the shipped examples) work unchanged on both engines.
- A few valid Python patterns are refused by Node with a precise message; the legacy engine still accepts them.
- Residual difference: code points assigned after the Python build's Unicode version.

## Alternatives rejected
- Store JavaScript syntax: breaks the legacy engine and every existing config.
- Run Python to evaluate regexes: makes Python a runtime dependency of the Node runtime.
- Ad hoc string replacement of `(?P<`: silently wrong for `$`, `.`, `\Z`, Unicode classes (E8: untranslated JS differed on 21 results
  and failed to compile 7 of 18 probe patterns).
- A third-party regex engine (re2/oniguruma bindings): native dependency, different semantics again.
