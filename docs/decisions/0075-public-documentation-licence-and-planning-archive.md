# 0075 Public documentation set, MIT licence, generated reference blocks and the archive of planning documents

Status: Proposed (V4, milestone M8, 2026-10-18). Owner: release area (F). Amends 0049 (documentation layout: the final set, the legacy folder, the eleven-question table, the traceability matrix and the CCAM reference are replaced; the rules for AI-readable documents stay). Relates to 0061 (the skill folder holds `SKILL.md` and the agent reference documents), 0063 (third-party notices), 0066 (the Python engine and its documents are gone), 0072 (the user interface has two languages).
Planned for a later 4.x release.

## Context
Owner decisions 7 and 10 make the repository public: English documents for users and contributors, a Vietnamese README, an MIT licence and notices for bundled code. The documents of the V3 plan were written for an internal build: a design set (`docs/design/00`-`06`, about 19,000 lines with critic issues, experiments and work-package slices), a plan, a contract registry, a requirements matrix, research notes, a change-request digest and status files. ADR 0049 planned a final set around the V3 cutover (legacy documents moved to `docs/legacy/`, a migration report, a traceability matrix). None of that fits a public 4.0: the legacy engine is removed (0066), there is no cutover to report, and the planning files would mislead readers and agents with statements that 4.0 superseded (a launcher that runs `npm ci`, a native SQLite addon, a Python oracle, a 380 px sidebar).

At 8ca9475 the planning set is referenced in many places: 42 of the 59 ADR files cite a `docs/design` or `docs/research` file by path, 32 ADR files carry a scratch folder or workspace path in their evidence lines, 81 of the 86 generated schema files and `docs/api/reference.md` carry a `docs/design/03-data-api-realtime.md` string from the generator, and 13 further files (comments, test titles, scripts, one applied migration) cite those paths.

## Decision
1. **Audience and languages.** User and contributor documents are English. `README.vi.md` is the only Vietnamese document and has the same top-level sections as `README.md`. The user interface has English and Vietnamese (0072). No other languages in 4.0.
2. **Final set.** Root: `README.md`, `README.vi.md`, `CHANGELOG.md` (Keep a Changelog, entry `4.0.0`), `CONTRIBUTING.md`, `SECURITY.md`, `LICENSE.txt`. `docs/`: `install.md`, `quickstart.md`, `configuration.md`, `cli.md`, `operations.md`, `troubleshooting.md`, `mcp.md`, `api.md`, `hooks.md`, `architecture.md`, `data-model.md`, `instance-isolation.md`, `ui-guide.md`, `development.md`, `testing.md`, `adr-index.md`, `decisions/`, `images/`, plus the generated `api/reference.md`. Skill folder: `SKILL.md` and `reference/` (agent oriented, self-contained because the plugin copy contains only that folder), `LICENSE.txt`, `bundle/THIRD-PARTY-NOTICES.txt`. Removed from the V3 set: `docs/legacy/`, `migration.md`, `traceability.md`, `ccam-reference.md`, `ui-decision-record.md`, `changelog.md` (replaced by the root file).
3. **Rules for technical documents** (from 0049, kept): a one-sentence purpose, `Applies to`, `Read next`; every behaviour claim names its source of truth (a code path, a schema or a test); tables and numbered steps over prose; a closing `Invariants` section with test ids and `Safe to change independently` / `Change together`; no private data; generated sections marked. Guides for users (`install`, `quickstart`, `troubleshooting`, README) are exempt from the closing sections.
4. **Generated reference blocks.** `scripts/gen-docs.mjs` writes the command and option tables (from `mcs help --json`), the configuration key table and the environment table (from the shared catalogues), the ADR index and the agent copy of the command reference between marker pairs; `--check` compares byte for byte and runs in `npm run ci` as `docs:check`. The same gate validates every command line shown in a document against the CLI definition, and requires every configuration key to appear in `docs/configuration.md`. `docs/api/reference.md` and `schemas/` stay generated by `gen-schemas.mjs`.
5. **Licence.** MIT. The holder line reads "monitoring-claude-sessions contributors" unless the owner names someone. `LICENSE.txt` exists at the repository root and inside the skill folder (the plugin cache copies only the skill folder) with identical bytes; `plugin.json`, the marketplace entry and every `package.json` carry the SPDX id `MIT`. Third-party notices for everything that is bundled are the file `bundle/THIRD-PARTY-NOTICES.txt` generated by the bundle pipeline (0063), including the libraries that a dependency embeds in its own build (the MCP SDK's validator, 0060). Development tools that are not shipped (the `axe-core` dev dependency, 0077) are not in the notices.
6. **Planning documents leave the repository.** `docs/design/**` (the seven design documents, the plan, the reconciliation log, the contract registry, the requirements matrix, the change-request digest, the handoff note, the status file and any V4 successor of them) and `docs/research/**` (seven research notes) are copied to a private archive outside the repository (the maintainer chooses the folder) and removed by the lead in one commit after the new documents exist. `docs/decisions/**` stays: ADRs are the record of why. Their citations of design sections by number or path are historical; `docs/adr-index.md` says so in one sentence and the documents check treats `docs/decisions/` as the only place that may name the archived folders. Code comments that cite a design section by number stay (rewriting thousands of comments is out of scope); new code cites an ADR or a final document.
7. **Text policy.** The text gate (`check-text`) allows Vietnamese letters only in `README.vi.md`, in the catalogue file `vi.ts` and in compiled web assets; it rejects e-mail addresses, home paths of real users, token shapes and long hex strings everywhere else, with an allow file whose entries carry a reason. The Python-removal guard (0066) applies to documents too.
8. **Versioning.** One version number in `plugin.json`, the marketplace entry and every `package.json`, written by `set-version.mjs`; the CHANGELOG entry `4.0.0` is written from the code and the ADRs, not from memory.

## Consequences
- A reader of the public repository sees user documents, maintainer documents, ADRs and generated references; the history of how it was planned is not part of it.
- Maintainers lose the design text as a reference. The new `architecture.md` and `data-model.md` replace it for 4.x, and the archive keeps the old text for the owner.
- The ADRs contain citations to documents that are not in the repository. That is accepted and stated once in the index.
- Documents cannot drift silently in their tables and commands, but prose still can; the verifier's spot checks and the replay log are the guard for prose.
- The Vietnamese README is a second copy to keep in step; the section-parity rule catches missing sections, not meaning.

## Alternatives rejected
- Keep `docs/design/` in the repository under an "archive" folder: it ships 19,000 lines that contradict 4.0 in places and invites agents to follow them.
- Rewrite all ADR citations and scratch paths by hand: wide churn for little value; only the scratch and home paths are scrubbed (they are personal data), the citations stay.
- A documentation site generator (VitePress, Docusaurus): a new dependency and build for a project that ships Markdown; GitHub renders it.
- Full Vietnamese documentation: a second set to maintain with no owner request; the README and the UI are in Vietnamese.
- Keep `docs/legacy/` for one release: the engine it describes cannot run any more (0066).
- LICENSE only at the repository root: the plugin copy would ship without it.
