## 1. Scope and non-scope

In scope: the SPA in `runtime/packages/web` (routes, components, styles, data layer, realtime client, tests, build output consumed by
`packages/server`), the E2E suite that drives it, and the TypeScript demo/fixture builder the E2E suite needs (section 11.5).

Not in scope (other designers): API handlers, SSE server, DB, lifecycle derivation, token math, CLI. The UI never derives lifecycle state,
token totals, task states or ingestion health itself: it renders what the API returns (master brief section 11: "do not duplicate the same
business logic"). The only client-side derivations are presentation (grouping, filtering already-loaded rows, formatting) and the
connection/freshness model, which only the client can observe.

**The UI is read-only.** It issues only `GET` requests and one `EventSource`. Mutations (export, backup, cleanup, hooks install, config
changes) stay CLI commands; the Settings page shows the exact command with a copy button (ADR 0031). This keeps the Host/Origin guard
the only security boundary and removes CSRF from the threat model.

Rules:
1. All routes render inside `AppShell` through a layout route `<Route element={<AppShell/>}>` that renders `<Outlet/>`.
2. Each route element is wrapped in `RouteErrorBoundary` with `resetKeys={[location.pathname]}` (navigation resets a crashed route).
3. Lazy routes use `React.lazy` + `<Suspense fallback={<PageSkeleton/>}>` inside the route boundary.
4. Server history fallback (S-1, section 13): every `GET` whose path does not start with `/api/` or `/assets/` and whose `Accept`
   contains `text/html` returns `index.html` with `Cache-Control: no-store`. Unknown `/api/v3/*` returns the JSON 404 envelope.
5. On every pathname change: scroll `#main` to top (not when only search params change), set `document.title`, move focus to the page
   `<h1 tabIndex={-1}>` (`usePageChrome(title)`). Focus is not moved on the first load (keeps focus where the browser put it).
6. `/tasks` and the URL parameter `task` are UI-only names (the brief's "task board"). The API calls the entity a **work item**
   (`GET /api/v3/work-items`, query `workItem`, `SessionSummary.workItemIds`, 03 5.1/5.4) because "task" is already the monitoring task
   (`--task <slug>`). `data/endpoints.ts` maps the UI names to the API names; no UI code sends `task` to the API.

### 3.2 URL parameter schema (UI-I10)

One module `src/lib/url-state.ts` owns parsing and serialisation. Each route declares a spec (an object of codecs); `useUrlState(spec)`
wraps `useSearchParams` and returns `[state, setState, ignoredKeys]`.

```ts
// src/lib/url-state.ts
export const INVALID: unique symbol = Symbol('invalid');
export interface ParamCodec<T> {
  readonly key: string;                          // URL key
  readonly default: T;                           // omitted from the URL when equal (arrays compared element-wise)
  parse(raw: string | null): T | typeof INVALID; // total: never throws
  format(v: T): string;                          // canonical text
}
export type Spec<S> = { readonly [K in keyof S]: ParamCodec<S[K]> };
export interface Parsed<S> { value: S; ignored: string[] } // keys present but invalid or unknown (keys only, never values)
export function parseUrlState<S>(spec: Spec<S>, sp: URLSearchParams): Parsed<S>;
export function formatUrlState<S>(spec: Spec<S>, s: S): URLSearchParams; // defaults omitted, keys in spec order
export function text(key: string, max: number): ParamCodec<string>;                  // trim, cap at max, default ''
export function oneOf<T extends string>(key: string, values: readonly T[], def: T): ParamCodec<T>;
export function setOf<T extends string>(key: string, values: readonly T[]): ParamCodec<T[]>; // comma list; dedupe; order = `values` order; any unknown member -> INVALID
export function flag(key: string): ParamCodec<boolean>;                              // '1' -> true, absent -> false, else INVALID
export function intRange(key: string, min: number, max: number): ParamCodec<number | null>;
export function idText(key: string): ParamCodec<string>;                             // any chars, max 200 (legacy cap)
export function timeRange(defaultPreset: Preset): Spec<{ range: TimeRange }>;        // multi-key codec (range | from,to)
export type Preset = '1h' | '6h' | '24h' | '7d' | '30d' | 'all';
export type TimeRange = { kind: 'preset'; preset: Preset } | { kind: 'custom'; from: string; to: string | null };
```

`useUrlState` algorithm:
1. Parse with `parseUrlState`. Unknown keys and `INVALID` values go to `ignored`; such fields take their default.
2. If `ignored.length > 0` or the canonical text differs from `location.search`, replace the URL once with the canonical form
   (`setSearchParams(canonical, { replace: true })`) and expose `ignored` so the page `FilterBar` shows a dismissible note:
   "Ignored invalid or unknown filter: <keys>".
3. `setState(patch, { push = false })` merges, formats and calls `setSearchParams(next, { replace: !push })`. Text inputs keep local
   state and write after 250 ms of no typing; selects and checkboxes write immediately. Filters replace history; route and tab changes push.
4. Cursors, loaded page counts and scroll positions are never written to the URL.

Time range: `range=<preset>` or `from=<ISO>[&to=<ISO>]`. Valid when `Date.parse` succeeds and `from < to`. The default preset of
`/sessions` derives from instance `windowHours` (<=1 -> `1h`, <=6 -> `6h`, <=24 -> `24h`, <=168 -> `7d`, else `30d`); the client sends
presets as `range=<preset>` and the server resolves them with its own clock (S-4), so browser clock skew cannot shift the window.

### 3.3 Deep links and legacy links

- Session `/sessions/<sessionId>`; subagent `?agent=<agentId>`; transcript entry `?tab=transcript&i=<index>`; timeline event
  `?tab=timeline#ev-<eventId>` (scrolls to the row when loaded; otherwise the page loads the page that contains it with `around=<eventId>`,
  S-6).
- "Copy link" (legacy) copies `location.origin + pathname + canonical search` of the current view.
- **Legacy hash links** (`/#sid=<id>&agent=<id>`, must-preserve #1): `LegacyHashRedirect` runs in `App` before routes render. When
  `location.pathname === '/'` and `parseHash(location.hash).sid !== ''`, it navigates with `replace` to `/sessions/<sid>?tab=transcript`
  (+ `&agent=<agent>`). Values are capped at 200 chars (ported `parseHash`). A `hashchange` listener repeats the check.

### 3.4 Not found and error boundaries

| Case | Rendering |
|---|---|
| Unknown path | `NotFoundPage`: h1 "Page not found", the requested path as text, links to Overview and Sessions. |
| Unknown session (API `404 session_not_found`) | `ErrorState kind="not-found"` with legacy text "The monitor does not know this session. It may be outside the session window or belong to another task." + link "Back to sessions". 404 is not retried. |
| Unknown agent (`404 agent_not_found`) | Banner in the detail page "Agent <id> is not part of this session" + link to the main agent. |
| Transcript file deleted (`410 transcript_gone`) | Transcript tab: `ErrorState kind="gone"` "The transcript file of this session no longer exists (Claude Code may have cleaned it up). Monitor events and token totals are still shown." Not retried. |
| Render exception in a route | `RouteErrorBoundary` fallback `ErrorState kind="crash"`: "This view failed to render." + "Reload view" (resets the boundary) + "Copy error details" (error name, message, component stack; no data values). `console.error` only. |
| Render exception in a panel, tile or chart | `PanelErrorBoundary` with inline `ErrorState size="inline"`; the rest of the page keeps working. |
| Exception in the shell | `AppErrorBoundary` at the root: full-page fallback with "Reload page". |
| Query errors | Never thrown to boundaries (`throwOnError: false` globally); rendered by the owning component via `ErrorState`/`StaleDataIndicator`. |

Error boundaries: one class component `src/app/ErrorBoundary.tsx` (`getDerivedStateFromError`, `componentDidCatch`, prop
`resetKeys: readonly unknown[]`, prop `fallback(props: { error: Error; reset(): void }): ReactNode`). No `react-error-boundary` dependency.

#### 4.4.2 AgentTree

Data: flat `AgentNode[]` from `GET /sessions/:id/agents`. `buildAgentTree(agents)` (pure, `lib/agent-tree.ts`):
1. Index by `id`. For each agent, parent = `parentAgentId` if present in the index, else the session root.
2. Agents whose `parentAgentId` is set but missing are attached to the root with `orphan: true` (rendered with tag "parent not loaded").
3. Cycle guard: walk parents with a visited set; an agent on a cycle is attached to the root with `orphan: true`.
4. Children of each node are grouped with the ported `groupAgents` (plain subagents first as "Subagents", then "Workflow <name>"),
   each group with `stateSummary` ("2 running, 5 completed"). `AgentNode.workflow` is an object (03 5.5): the group key is
   `workflow.runId`, the title `workflow.name ?? workflow.runId`, and the header also shows the run's own `workflow.state` badge.
5. Sort inside a group: `startedAt` ascending, then `id`.

Rendering: nested `<ul role="list">` (not ARIA `tree`, to avoid a custom keyboard model); each group header is a `Disclosure` button with
aria-expanded and the count + summary; groups with more than `LAZY_AGENT_THRESHOLD = 30` agents start collapsed; inside a group,
`AGENT_PAGE = 100` rows then "Show N more". Row: StateBadge, label, agent type, model, last activity, token line + lower-bound badge,
error count, link "Open transcript" (`?tab=transcript&agent=<id>`). Selected agent row has `aria-current="true"`.
Rule shown in the header: "A subagent ending never completes its parent" (D9) when the parent is not terminal but children are.

#### 4.4.3 TranscriptViewer (port of legacy `timeline.js`, must-preserve #14-#27)

Toolbar (`TranscriptToolbar`, `role=search`): search input (`tq`, 150 ms debounce like legacy; Esc clears when non-empty; `/` focuses),
"Search whole transcript" button, tool select (options rebuilt only when `collectToolNames` result changes; keeps a vanished selected name
as an extra option), "Errors only" (`terr`), Prev/Next error, five kind checkboxes, "Newest first" (prefs `newestFirst`), "Follow new
events", jump form ("#N", "HH:MM[:SS]", ISO; `parseJump`), count line `role=status`: "Showing V of U loaded items · N errors · events #A to
#B of TOTAL".

Data hook (section 5.4): `useTranscriptWindow(sessionId, agentId)` returns
```ts
export interface TranscriptWindowState {
  gen: number;                   // generation: bumps on reset/replaceWindow; async results with an older gen are dropped
  events: TranscriptEntry[];     // ascending by i, deduped (mergeEvents)
  base: number; total: number; next: number; partial: boolean; skippedBytes: number;
  status: 'idle' | 'loading' | 'ready' | 'error' | 'not-found' | 'gone';   // gone = 410 transcript_gone
  error: ApiError | null; lastSuccessAt: number | null;
  olderLoading: boolean; capped: boolean;       // capped: events.length reached MAX_TRANSCRIPT_EVENTS
}
export interface TranscriptWindowApi {
  state: TranscriptWindowState;
  loadOlder(): Promise<number>;        // before=<first i>, limit 250; returns olderAdded; announces "Loaded N older events"
  jumpTo(target: JumpTarget): Promise<number | null>; // locate -> window replace when not loaded; returns index or null
  refresh(): void;                     // coalesced "after=next" fetch (single in-flight + again flag; up to 3 chained while next < total)
}
```
Rendering rules (all from legacy, section 1.8 of the research file):
1. Units = `pairEvents(events)`; visibility = `unitVisible(u, filters)`; rows are rendered for all units and hidden ones get the
   `hidden` attribute (not unmounted) so scroll, focus and `<details>` state survive filtering. Rows are `memo`ised with props
   `(unit, sig = unitSig(unit), open, expanded, now-for-active-only)`; only active tool rows subscribe to the 1 s clock.
2. Row keys `e<i>`. Order: newest first (default) or oldest first; the "Load older" row sits at the far edge; `ResumeFollowButton`
   ("Resume following (N new)") floats at the latest edge.
3. Plain rows: kind icon + label, error badge, `#i` button (copies index), time (`RelativeTime mode="clock"`), copy text. Body: `Markdown`
   for `prompt` and `say`; preformatted text for `think` (italic, muted) and `result`. `ClampedText` at 1,500 chars.
4. Tool unit: `<details>` with status pill (running 12s / ok 3s / failed 3s via `toolDurationSec`), name, one-line summary, `#i`, time;
   body: copy input / copy tool id / `#i`, pretty-printed input (`JSON.parse` + `JSON.stringify(v, null, 2)`, raw text fallback), result
   block "Result" or "Result: error" (4 px left border in failed tone). Open state in a `Set<string>` keyed `${sessionId}|${agentId}|${key}`
   held in the viewer (survives updates; must-preserve #24). `hide-result` class when Results kind is off.
5. Follow: `useReducer(followReducer, undefined, initialFollow)` (ported verbatim, identity-preserving). `onScroll` dispatches
   `{type:'scroll', atEdge: atLatestEdge(el, newestFirst)}` (24 px tolerance); new events dispatch `{type:'events', count}`; `f` toggles.
6. Scroll anchoring (`useScrollAnchor(scrollerRef, deps)`): before applying a merge/filter/order change, `captureAnchor()` stores the
   first visible row key and its offset from the scroller top; in `useLayoutEffect` after the commit, `restoreAnchor()` adjusts
   `scrollTop` by the delta. When following, the effect snaps to the latest edge instead. Scroller CSS `overflow-anchor: none`.
   Verified feasible with `content-visibility: auto` rows (experiment E4: drift 0 px).
7. Error stepping: `stepError(keys, cursor, dir)` over visible error units in display order, no wrap; cursor resets when filters change;
   announces "Error P of T" or toasts "No more errors in that direction" / "No errors in the loaded events".
8. Jump: `parseJump` -> `GET .../transcript/locate` -> if index not loaded, `replaceWindow` (fetch `after=max(base, i-15)`), follow off,
   bump `gen` -> scroll target into view (`block: 'center'`), focus it, `is-target` outline, open tool row if the jump hit its result
   index or it failed. A hidden target clears `tq`/`tool`/`terr` and toasts "Filters cleared to show #N". The `i` URL param triggers the
   same flow on load and is removed (replace) after the jump completes.
9. Whole-transcript search: `useTranscriptSearch({ session, agent, q, kinds, tool, errors })` (API query names of 03 6.1
   `searchTranscript`; TanStack query, enabled only on button press; key includes all params; `AbortSignal` passed; previous request
   cancelled automatically by key change; a response whose echoed `query` differs from the current one is dropped, 03 6.4). Results panel
   (`TranscriptSearchResults`): rows `#i  HH:MM:SS  Kind name  snippet`; notes: `truncated` -> "Showing the first N matches";
   `complete === false` -> the server's `coverage.note` plus "Not every part of the transcript was searched" (brief 8.5: never claim the
   entire transcript when only part was searched); `429 search_busy` -> "Another search is running; try again in a moment". Clicking a row = jump. Closing returns focus to the button.
10. Partial index: v3 windows address the whole file (`base` is always 0, 03 7.3); `partial === true` means `pendingBytes > 0` bytes are
    not indexed yet. `PartialBanner` (role=status) "Indexing this transcript: N MB not indexed yet; the newest entries may be missing"
    while `partial`; it disappears on the next window without pending bytes. "Load older" stays a toolbar action (disabled with
    tooltip when the first loaded index is 0 or `capped`).
11. Transcript reset (`total < next` in a response): reset reducer, toast "The transcript was reset; reloading events", refetch.
12. Window cap: `MAX_TRANSCRIPT_EVENTS = 5000`. `loadOlder` refuses when `events.length >= cap` (`capped: true`, banner "Window limit
    reached. Use Jump to view another part."). New events appended beyond the cap drop the oldest events from the window (and set
    `base` accordingly) only while following; when not following, the window keeps its position and the newest are counted as unseen
    without being stored (fetched again on resume). Proved by `transcript-reducer.test.ts`.
13. Rows use `content-visibility: auto; contain-intrinsic-size: auto 72px` (ADR 0038, experiment E4).

```ts
  get<T>(name: EndpointName, path: string, schema: ResponseSchema<T>,

```
Algorithm of `get` (port of legacy `createApi.get`, extended):
1. Build URL `baseUrl + '/api/v3' + path` + query (`null`/`undefined`/`''`/`false` omitted, arrays joined by `,`, `true` -> `1`).
2. `inFlight++`. Combine the caller signal with a timeout controller (`AbortSignal.any([caller, timeoutCtrl.signal])`).
3. `fetch(url, { signal, headers: { Accept: 'application/json' }, cache: 'no-store', credentials: 'same-origin' })`.
4. Network failure: caller aborted -> throw `ApiError('aborted')` and **do not** count a failure (navigation is not an outage);
   timeout -> `timeout`; else `network`.
5. Read text; `JSON.parse` (failure -> `parse`). Non-2xx: parse the envelope `{ error: { code, message, requestId } }` with the shared `ErrorEnvelope` schema (an envelope that fails it, or
   a code outside the `ErrorCode` union, yields `code: null`);
   message from `describeFailure('http', status, envelope.message)`; kind `http`.
6. 2xx: `schema.safeParse(body)`; failure -> `ApiError(kind 'contract', message "The monitor sent data this page does not understand
   (<endpoint>)")`; the zod issue paths (never values) go to `console.warn` in dev builds only.
7. Success: `lastSuccess = now()`, `failures = 0`. Failure (not aborted): `failures++`, `lastError = {...}`. `inFlight--` in `finally`.
   Notify subscribers (coalesced with `queueMicrotask`).
Retries are owned by TanStack Query (`retry` function below), not by the client.

Error codes (03 5.2 catalogue, imported as `ErrorCode`; the UI branches on HTTP status first and on the code only where listed):

| Status / code | UI behaviour |
|---|---|
| `400 cursor_invalid` | infinite list restarts at the first page (5.3 rule 2) |
| `400 validation_failed`, `param_repeated`, `range_invalid`, `range_too_large`, `filter_requires_scope`, `query_too_short` | `ErrorState` "The monitor rejected this filter: <envelope message>"; the filter bar stays editable; not retried |
| `403 host_not_allowed`, `origin_not_allowed`, `cross_site_request` | full-page `ErrorState` "The monitor refused this page's address. Open the URL printed by `$MCS status --task <slug>`."; not retried |
| `404 session_not_found`, `agent_not_found`, `event_not_found`, `work_item_not_found`, `route_not_found` | not-found states of 3.4; not retried |
| `404 panel_disabled` | panel removed (4.4.1 step 2) |
| `410 transcript_gone` | transcript `gone` state (3.4) |
| `429 search_busy`, `export_busy` | retried once after `Retry-After` (2 s) seconds; then "busy" text |
| `500 internal_error` | generic failure text with the request id; retried (5.2) |
| `503 db_busy`, `disk_full`, `shutting_down`, `stream_limit` | retried with backoff; `disk_full` also shows "The monitor's disk is full" in HealthDetails |

### 5.3 Cursor pagination with infinite queries

```ts
useInfiniteQuery({
  queryKey: qk.sessions(iid, q),
  queryFn: ({ pageParam, signal }) => api.get('sessions', routes.listSessions.path, routes.listSessions.response, { query: { ...q, cursor: pageParam, limit: 100 }, signal }),
  initialPageParam: null as string | null,

  maxPages: 10,                                     // verified option exists in query-core 5.104.1 (E1)
  placeholderData: keepPreviousData,                // filter change keeps old rows visible, marked "Updating..." (aria-busy)
});
```
Rules:
1. Cancellation: TanStack passes `signal`; changing filters changes the key, so the old request is aborted (`ApiError aborted`, not
   counted as failure). Typing debounce (250 ms) bounds request rate.
2. Stable sort: the server guarantees a total order (`sort`, then `id` in the same direction as tie-break, 03 5.3, S-3); the UI never
   re-sorts server pages. A rejected cursor (`400 cursor_invalid`: its route, sort, direction or filter hash no longer matches, 03 5.3) ->
   `resetQueries` for that key + toast "The list changed; reloaded from the top"; not counted as an outage.
3. When `maxPages` drops the oldest page while loading more, the table shows `LoadMore capped` text instead of silently losing rows: the
   UI does not load beyond `maxPages` (the button is replaced by the capped note).
4. Live changes do not reorder loaded pages (section 5.5 rule R3).

### 5.4 Transcript window (not TanStack; ADR 0031)

The transcript is index-addressed and append-only with windows (`base`, `next`, `total`, `partial`), and the legacy client logic
(`mergeEvents`, generation guard, `replaceWindow`, reset detection) is proven; it maps onto a reducer, not onto a page cache.

`transcript-reducer.ts` (pure, tested):
```ts
type Action =
  | { type: 'reset'; gen: number }
  | { type: 'loaded'; gen: number; mode: 'tail' | 'after' | 'before' | 'window'; resp: TranscriptWindowResponse; at: number }
  | { type: 'failed'; gen: number; error: ApiError; at: number };
// 'loaded' with gen !== state.gen -> ignored (stale-response guard). mode 'after' with resp.total < state.next -> needsReset=true.
// merge uses mergeEvents(); cap rule from 4.4.3 step 12; base/next/total/partial/skippedBytes copied from resp ('before' keeps next).
```
`useTranscriptWindow` effects:
1. On `(iid, sessionId, agentId)` change: abort in-flight, `gen++`, dispatch `reset`, fetch tail (`after=-1`, i.e. last 250).
2. `refresh()` (from a stream `transcript/append` change whose `sessionId` and `data.agentId` match this viewer, or `data: null` for this
   session, or from the !L interval): if a fetch is in flight set `again = true`; else fetch `after=next`; repeat up to 3 times while
   `next < total` (legacy chained fetches). The change carries only `{ agentId, sizeBytes }` (03 9.2); the window response is the truth.
3. `needsReset` -> toast + step 1. A `410 transcript_gone` response -> `status: 'gone'` (3.4), no further refreshes until the session or
   agent changes. Responses also carry `fileState` and `pendingBytes` (03 7.3); `pendingBytes > 0` drives the partial banner (4.4.3 step 10).
4. Unmount: abort, clear interval (UI-I14).

### 5.5 Reconciliation (`stream/reconcile.ts`, `stream/patch-ledger.ts`)

Every entity carries `seq` (the change-log sequence of its last change, 03 9.1, S-10). Every snapshot response carries `asOfSeq` (the
change-log head read in the same synchronous step as the data, 03 5.1). Stream frames are hydrated at send time, so `data.seq` can exceed
the frame `seq` (03 9.3); rule R1 compares entity `seq` values only.

Rules:
- R1 (no regression): a patch for entity E is applied only if `incoming.seq > cached.seq`. Equal or older -> ignored.
- R2 (no duplicates): lists are keyed by entity id; appends dedupe by `id` (events, a number) and by `i` (transcript).
- R3 (stable views): patches update rows **in place**; membership and order changes of a list (a new session appears, a sort key
  changed) do not reorder loaded rows. Instead the list gets `pendingChanges++` and shows a "List changed: Refresh" button (`role=status`
  text "3 sessions changed"). Exception: when only the first page is loaded and the user has not scrolled the list (scrollTop < 8 px),
  the first page is invalidated (debounced 2 s) so the default view stays current without user action.
- R4 (late snapshot): a snapshot response older than patches already applied must not overwrite them. `PatchLedger` keeps the latest
  patch per entity key (`session:<id>`, `agent:<sid>:<aid>`, `workflow:<runId>`, `work_item:<id>`, `alert:<id>`) with its `seq` (LRU,
  2,000 keys). Every query function that
  returns entities passes its result through `ledger.reapply(result)`: for each entity in the result with `entity.seq < ledgerEntry.seq`,
  the ledger copy replaces it. Entries with `seq <= result.asOfSeq` are evicted from the ledger (the snapshot already includes them).
- R5 (reset): on `reset`, on a new `epoch`, on detected gap, on invalid message, or on instance change: clear the ledger, clear live buffers, then
  `queryClient.invalidateQueries({ queryKey: qk.root(iid) })` (active queries refetch; inactive ones are marked stale) and call `refresh()`
  on mounted transcript windows. On instance change: `queryClient.removeQueries({ queryKey: ['mcs'] })` instead (cache cleared), then
  refetch instance.

Resync requests arriving within one flush window (100 ms, 5.6) run R5 once.

`applyChange(change: StreamChange, ctx)` dispatch table (`StreamChange` of 03 9.2; pure where possible; `ctx` gives `queryClient`,
`ledger`, `liveBuffers`, `transcriptRegistry`). `data: null` always means "the referenced entity no longer exists or is not readable now":

### 5.6 Realtime client and connection/freshness model

#### Stream client (`stream/stream-client.ts`, ADR 0032)

Uses the browser `EventSource` through an injectable factory, with **client-owned reconnect**: on any `error` event the client closes
the source and reconnects itself with backoff and an explicit `since=<lastSeq>` query parameter. Reason (experiment E2): native
auto-reconnect resends the original URL (stale `since`) plus a `Last-Event-ID` header, and a non-200 response (`503`) moves the source to
`CLOSED` permanently. One code path is easier to test and reason about. Protocol: 03 9.2 (frames `hello`, `change`, `heartbeat`, `reset`;
query `since` + `epoch`; `503 stream_limit` beyond 16 streams, seen by `EventSource` as an `error`).

```ts
export type StreamStatus = 'idle' | 'connecting' | 'open' | 'backoff' | 'stopped';

  attempt: number; nextRetryAt: number | null; lastError: string | null;

}

  onEpochChanged(info: { epoch: string; runtimeVersion: string; codeStamp: string }): void;   // restarted server: refetch instance; offer reload when version/stamp differ
}
export type ResyncReason = 'reset' | 'gap' | 'invalid' | 'overflow' | 'head-ahead' | 'epoch';
export interface StreamClient { start(): void; stop(): void; retryNow(): void; snapshot(): StreamSnapshot; subscribe(fn: () => void): () => void }
export interface EventSourceLike { readonly readyState: number; onopen: ((e: Event) => void) | null; onerror: ((e: Event) => void) | null;
  addEventListener(type: string, fn: (e: MessageEvent<string>) => void): void; close(): void }
```

State table:

| State | Event | Guard | Next | Actions |
|---|---|---|---|---|
| idle | `start()` | - | connecting | `es = factory(url + '?since=' + (lastSeq ?? startSeq) + '&epoch=' + (epoch ?? expectedEpoch))`; arm connect timeout `max(10000, 2*heartbeatMs)` |
| connecting | `open` | - | open | `openedAt = now`; `attempt = 0`; arm watchdog |
| connecting/open | `hello` msg | `instanceId !== expected` | stopped | `close`; `onInstanceChanged(id)` |
| connecting/open | `hello` msg | `epoch !== (epoch ?? expectedEpoch)` | (same) | `epoch = msg.epoch`; `lastSeq = msg.headSeq`; `resync('epoch')`; `onEpochChanged(msg)` (the server also sends `reset(epoch_changed)`; R5 runs once per flush window) |
| connecting/open | `hello` msg | ok | (same) | `epoch = msg.epoch`; `serverHeadSeq = headSeq`; `heartbeatMs = msg.heartbeatMs` |
| open | `change` msg | invalid JSON or schema | open | `counters.invalid++`; `resync('invalid')` |
| open | `change` msg | `seq <= lastSeq` | open | `counters.duplicates++` (ignored) |
| open | `change` msg | `lastSeq !== null && seq > lastSeq + 1` | open | `resync('gap')`; `lastSeq = seq`; message dropped (the refetch covers it) |
| open | `change` msg | `seq === lastSeq + 1` or `lastSeq === null` | open | `lastSeq = seq`; enqueue; flush on `requestAnimationFrame` or 100 ms, whichever first (batching) |
| open | queue length > `maxQueue` | - | open | drop queue; `resync('overflow')` |
| open | `heartbeat` msg | `msg.epoch !== epoch` | open | as the `hello` epoch row |
| open | `heartbeat` msg | - | open | `lastHeartbeatAt = now`; `serverHeadSeq = headSeq`; if `headSeq === lastSeq` -> `inSyncAt = now`; if `headSeq > lastSeq` on two consecutive heartbeats -> `resync('head-ahead')` and `lastSeq = headSeq` |
| open | `reset` msg | - | open | `lastSeq = headSeq`; `lastResetReason = msg.reason`; `resync('reset')` |
| connecting/open | `error` event | - | backoff | `es.close()`; `attempt++`; `delay = nextDelay(1000, attempt)` (2, 4, 8, 16, 30, 30 ... s); `nextRetryAt = now + delay`; timer |
| open | watchdog | `now - max(openedAt, lastMessageAt, lastHeartbeatAt) > 2.5 * heartbeatMs` | backoff | as `error` with `lastError = 'no heartbeat'` |
| connecting | connect timeout | - | backoff | as `error` with `lastError = 'connect timeout'` |
| backoff | timer / `retryNow()` / window `online` | - | connecting | as `start()` |
| any | window `offline` | - | backoff | close; no timer until `online` (status text "Offline") |
| any | `stop()` | - | stopped | close, clear all timers, remove window listeners (UI-I14) |

`resync(reason)`: `counters.resyncs++`, `onResync(reason)` (rule R5). Message validation uses the shared stream schemas of
`shared/src/api/stream.ts` (03 9.2, S-10). `inSyncAt` also updates after every successfully applied batch. A `503 stream_limit` (more
than 16 tabs) is an `error` event: the client backs off and the connection model shows `polling` while REST works (03 9.5).

`StreamProvider` (React): waits for `useInstance` success, creates one client per `instanceId` with `expectedEpoch = instance.epoch` and
`startSeq = instance.headSeq`, `start()` in `useEffect`, `stop()` in the cleanup. `onEpochChanged` refetches `useInstance` and
`useConfigInspection`; when `runtimeVersion` or `codeStamp` differ from the page's instance info, a toast offers "The monitor was
updated: Reload page". Strict Mode double-invokes effects in dev: start/stop/start is safe because `stop()` is idempotent and `start()` from `stopped`
creates a new source. Exposes `useStreamSnapshot()` via `useSyncExternalStore`.

#### Connection/freshness model (`lib/connection-health.ts`, pure; `stream/useFreshness.ts`)

Ported and extended from legacy `computeHealth` (thresholds kept).

```ts
export type ConnectionState = 'connecting' | 'live' | 'polling' | 'reconnecting' | 'offline';
export interface ConnectionView {
  state: ConnectionState;
  stale: boolean;               // now - lastSyncAt > staleAfterMs
  lastSyncAt: number | null;    // max(stream.inSyncAt, min over core endpoints of lastSuccess)  (see step 4)
  ageMs: number | null;
  retryAt: number | null;       // soonest of stream.nextRetryAt and failing queries' next retry
  lastError: { source: string; message: string; t: number } | null;
}
export function computeConnection(i: {
  now: number; staleAfterMs: number; online: boolean;
  stream: Pick<StreamSnapshot, 'status' | 'inSyncAt' | 'nextRetryAt' | 'lastError'>;
  core: readonly EndpointRecord[];   // instance (until first success), then health + the active page's primary list endpoint
}): ConnectionView;
```
Algorithm:
1. If no core endpoint was touched and the stream never opened -> `connecting`.
2. If `online === false` -> `offline`.
3. `apiDown` = some core record with `failures > 0` and (`lastSuccess === null ? failures >= 3 : now - lastSuccess >= staleAfterMs`)
   (legacy "lost" rule).
4. `lastSyncAt` = if stream `open` then `stream.inSyncAt` else the minimum `lastSuccess` of core endpoints (legacy: OLDEST core success).
5. State: stream `open` and not `apiDown` -> `live`; stream not open and no core failing -> `polling`; `apiDown` -> `offline`; else
   `reconnecting`.
6. `stale = lastSyncAt !== null && now - lastSyncAt > staleAfterMs`.
`staleAfterMs` = `instance.staleAfterMs` (config `poll.stale_after_ms`, default 15000, 03 6.2; one value for every client, which settles
the legacy 15000/20000 mismatch). Before `/instance` first succeeds the state is `connecting` and no staleness is computed.

#### Ingestion view (UI-I4)

```ts
export type IngestionDisplay = 'ok' | 'degraded' | 'stalled' | 'down' | 'disabled' | 'unknown';
export interface IngestionView { display: IngestionDisplay; reasons: string[]; asOf: number | null; known: boolean }
export function computeIngestionView(health: HealthReport | undefined, healthRecord: EndpointRecord | null, conn: ConnectionView, now: number): IngestionView;
```
1. No health ever -> `{display:'unknown', known:false}`.
2. `known = conn.state in ('live','polling') && healthRecord.lastSuccess !== null && now - healthRecord.lastSuccess <= staleAfterMs`.
3. `known` -> `display = health.ingestion.status`; else `display = 'unknown'`, `reasons = ['Last known: <status>, <age> ago']`.

### 5.7 Live buffers and pause/resume (`stream/live-buffer.ts`)

```ts
export interface LiveBufferOptions<T> { key(t: T): string; accept(t: T): boolean; headCap: number /* 500 */; pausedCap: number /* 500 */ }
export interface LiveBufferState<T> { head: T[] /* newest first */; paused: boolean; buffered: T[]; dropped: number; seen: Set<string> /* bounded with head+buffered */ }
export type LiveBufferAction<T> =
  | { type: 'offer'; items: T[] } | { type: 'pause' } | { type: 'resume' } | { type: 'snapshot'; asOfSeq: number; seqOf(t: T): number } | { type: 'clear' };
export function liveBufferReducer<T>(s: LiveBufferState<T>, a: LiveBufferAction<T>, o: LiveBufferOptions<T>): { state: LiveBufferState<T>; effect: 'none' | 'refetch-first-page' };
```
1. `offer` (live): accepted, unseen items are prepended to `head`. If `head.length > headCap` -> `effect: 'refetch-first-page'` and
   `head = []` (the first page refetch contains them; UI-I7).
2. `offer` (paused): accepted, unseen items go to `buffered` (newest first) up to `pausedCap`; beyond it `dropped += n` (items discarded).
3. `resume`: if `dropped === 0` -> `head = buffered ++ head` (dedupe), `buffered = []`; else `effect: 'refetch-first-page'`, clear both.
   Announce "Resumed: N new events".
4. `snapshot` (first page refetched): remove from `head` and `buffered` every item with `seq <= asOfSeq` (now in pages).
5. Pause is per feed instance (component state, not URL, not prefs). Bounded buffering satisfies brief 8.4.

### 11.5 Demo builder contract (`@mcs/testkit` `src/demo.ts`)

Ownership (06 6.1): `runtime/packages/testkit` is hosted and implemented by design 05 (slice S3: core modules incl. `hooks.ts` with

## 16. CHALLENGES

Status 2026-10-11: challenges 1 and 2 are adopted by the API design (03 9.2: named `heartbeat` frames, `since` + `epoch`,
`Last-Event-ID` precedence); they stay here as the record of why.

1. **D11 "heartbeat comments".** Comments are invisible to the `EventSource` API (E2), so the client cannot run a watchdog on them. Keep
   comments if proxies need them, but the server must also emit a named `heartbeat` event (no `id`) every `heartbeatMs` carrying
   `headSeq`. Without it the UI cannot distinguish "quiet but connected" from "half-open connection", and the stale indicator would be
   wrong for quiet instances. Alternative rejected: a fetch-stream SSE parser in the client (sees comments, but re-implements what the
   browser provides and adds code to test).
2. **D11 `Last-Event-ID` alone is not enough for a client-managed reconnect.** Native reconnect sends the header but reuses the original
   URL (E2), and after a non-200 response the browser stops reconnecting. The client therefore reconnects itself with `?since=<seq>`; the
   server must accept `since` and give the `Last-Event-ID` header precedence when both are present.
3. **D7 lists react-markdown + rehype-sanitize as the Markdown path (stack-versions section 9).** This design keeps the legacy Markdown
   subset parser instead (ADR 0034): it is already tested, needs no dependency, renders no links at all (stricter than sanitized
   Markdown) and preserves the current look. Revisit only if the owner wants richer Markdown.
4. **Legacy stale dimming (not a D item, a must-preserve behaviour).** Opacity 0.6 fails text contrast (E3); replaced by an outline +
   indicator (ADR 0033). Behaviour preserved: last good data stays visible and is clearly marked.
